01
The problem

Why the default looks AI-generated

The original BizzNex frontend was assembled from stock component libraries (Fluent UI, MUI) with drop-in cards, gradients and rounded boxes. It worked — and looked like every other tool built the same way. The root cause is distributional convergence: the industry defaults (Tailwind / shadcn) share one habit — containerization. Every element becomes a bordered, shadowed, rounded card, so screens collapse into a grid of near-identical boxes.

The design brief was therefore not "pick nicer colors" but change the grouping mechanism. The thesis that carried through every later decision:

Group with space, type and hairlines — never boxes. Delete every border and the structure should still read.

Research & north stars

Three research passes

  • Why AI UIs look generic — the containerization habit above; the fix is editorial grouping.
  • Container-less / editorial layout — named-line grids, whitespace (Gestalt proximity), hairline rules, asymmetric splits, bleed & overlap; data in borderless tables with tabular numerals.
  • Systems audit — how restrained products carry density without boxes.

North stars

  • Mercury, Linear, Attio, Stripe, Anthropic — data-dense but human.
  • AREA 17, RoAndCo — editorial studios, for type & grid discipline.

Type system

Hierarchy is carried by size & weight, not tint. Three families, each with a strict job:

Fraunces · serif
Business, run beautifully

Display, headings, folios, hero metrics, pull-quotes. Weights 400/500/600 + italic 500.

Plex Sans · sans
Body copy, buttons and inputs. The workhorse UI face — clear at 15px, letter-spacing −.006em.
Plex Mono · mono
12,480.00 · labels · § spec · nav · captions

All labels, spec strings, numbers/data, table headers, nav, captions, tags — tabular lining numerals.

Radius & borders

  • One radius token: --radius: 3px — "near-sharp, editorial."
  • Rectangles stay near-sharp; only marks (dots, avatars) round.
  • Checkboxes/switch knobs use 2px as the single fine exception.
  • No box borders — only hairlines: --rule (.18α) and --rule-soft (.09α).

Motion

  • One easing curve everywhere: cubic-bezier(.22, 1, .36, 1).
  • Durations: 120ms press · 200ms hover/color · 250ms transform · 500ms theme.
  • Set-pieces: hero rise 1s · aurora drift 34s · toast 300ms.
  • Static blocks never animate — motion is only entrances & hover.

  • Folio numbers in faint serif open every section (see 01–08).

06
Interaction model

"Use every feature at once" — four paradigms

A second, parallel exploration asked how a business owner could run many tools simultaneously. Four interactive prototypes were built on the same Aurora palette; only the interaction layer differed.

1 · Hybrid was recommended

Sidebar app; left-click opens a tool inline as a compact widget, right-click pops a floating resizable window. Dock + minimise. Data views stay full-page.

2 · Canvas ✕

Everything is a window — Dashboard, Projects, Tasks and every tool — launched from a 66px rail onto a dot-grid canvas. Max multitasking; boots with two windows open.

3 · Panels ✕ lightest

Tools toggle as light, draggable, closable panels. No resize, no minimise, no dock — the simplest step toward multitasking.

4 · Studio ✓ final · we build this

The Hybrid, evolved: left-click opens the tool's full-page version inline (like a data view); right-click pops the compact window. Uniform size, auto-dock.

Why Studio — and its exact rules

Canvas was too much (windowing the data views is disorienting and loses the readable full-page layouts). Panels was too little (no resize/minimise/dock caps multitasking). Hybrid was right but its inline mode showed only a cramped widget. Studio keeps Hybrid's dual trigger but upgrades the inline view to a full, feature-rich page — so one sidebar item yields both a full workspace and a floating utility.

  • Left-click a tool → opens its full-page version inline in the main area, exactly like Dashboard/Projects/Tasks. Header shows a § Tool spec-label, serif title, and an "Open in window ↗" button.
  • Right-click a tool → pops a floating window showing the tool's compact widget (not the full page) — the two-variant split is deliberate.
  • Uniform window size — every window opens at the Calculator's 280 × 380; users resize from there and the body scrolls on overflow.
  • Windows are draggable (title bar), resizable (min 240×150), minimizable, closable; focus raises z-order and deepens the shadow; new windows cascade by (x 96+i·34, y 92+i·30).
  • Dock (bottom-center, blurred) auto-shows on first window and auto-hides when the last closes.
  • Sidebar dot marks tools that currently have a window open (window state only; inline-open just marks the item active).
  • Notes owns an in-page search, so it was removed from the topbar's searchable set to avoid two search boxes.
07
Implementation

How it ships in apps/web

The design is not a mockup — it's the running React app. Here is exactly what implements each decision.

Stack

  • React 18 + TypeScript + Vite.
  • Redux Toolkit (auth + UI slices) & RTK Query (API).
  • react-intl for i18n; a single hand-written aurora.scss.
  • Dropped Fluent UI / MUI / framer-motion / styled-components / Google-Maps in favour of a lightweight custom Aurora layer.
  • Full stack: NestJS + Prisma + PostgreSQL API, JWT auth (see DEPLOYMENT.md).

App shell

  • 248px sticky sidebar + fluid main area (App.tsx → Sidebar, Topbar, WindowLayer, Dock).
  • Brand mark, two nav groups (Workspace · Tools), user footer with initials avatar & logout.
  • Topbar: BizzNex / Section breadcrumb, contextual search (Projects/Tasks only), "Open in window ↗", EN/ES/FR segmented switch, theme toggle.
  • Windowing state lives in layout/useWindows.ts; live drag/resize geometry stays inside each ToolWindow to avoid re-renders on pointer move.

The seven tools (views/tools/*)

  • Calculator — keypad + memory (MC/MR/M+/M−), history tape, business quick-calc (sales tax / tip & split / discount / profit margin).
  • Assistant (Brenda) — chat launcher across Google/YouTube/Reddit, suggestion & source chips, recent tape.
  • Notes — full CRUD, in-page search, persisted via the real API.
  • Publisher — compose once, multi-platform, live 0/280 char counter + preview, recent list.
  • Notifications — connect-gate → aggregated inbox with platform filters + refresh.
  • Newsletter — Compose / Analytics tabs, campaign ledger with status pills.
  • Events — category + radius search over a results ledger.

Each tool has two renderings: a rich full page (left-click / inline, in registry.tsx) and a compact widget (right-click / window, in widgets.tsx).

Rationale

Small decisions log

The details that are easy to miss — each is a deliberate choice, recorded so it survives future edits.

DecisionWhy
Warm paper, no pure whiteWhite + boxes is the "AI-generated" tell; a warm cream surface reads as considered and calm.
Exactly one accentA single flat accent forces hierarchy through type & space, not color — the anti-rainbow rule.
3px radius everywhereNear-sharp rectangles read editorial; only marks (dots, avatars) go round, so roundness signals "this is a mark."
Hairlines over bordersTwo rule alphas (.18 / .09) group content without drawing boxes — "delete every border and it still reads."
Asymmetric spacing scale6/12/20/34/56/92/140 grows non-linearly so whitespace itself creates rhythm and emphasis.
Mono for all data & labelsTabular numerals align in tables; uppercase mono spec-labels are the editorial fingerprint.
Aurora used exactly onceRestraint — one blurred mesh moment is a signature; everywhere would be noise.
5% film grainA barely-there fractal-noise overlay removes the flat-digital "screenshot" feel.
Accent lightens in dark mode#5B41E0 → #A897FF keeps contrast on warm charcoal without glare.
One easing curvecubic-bezier(.22,1,.36,1) everywhere makes motion feel like one hand; static blocks never move.
Uniform 280×380 windowsPredictable "Calculator size" for every tool; the user resizes rather than the app guessing.
Dock auto-hidesZero chrome when nothing is open — the dock earns its space only while windows exist.
Notes off the topbar searchNotes has its own in-page search; two search boxes would compete.
Full page vs compact widgetInline = focused work surface; window = glanceable utility. Same tool, two honest sizes.
Dropped the component librariesFluent/MUI impose the very card idiom the brief rejects; a thin custom layer keeps the system pure and the bundle small.
